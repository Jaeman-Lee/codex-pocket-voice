## 범위와 남은 개선

- 이번 브라우저 회귀는 합성 API 응답이며 실제 휴대폰 음성·백그라운드 제한·SSH 접속 성공과 구분한다.
- 로컬 실제 Codex 통합은 초기화·대화 조회까지 검증하며 모델 턴을 실행하지 않는다.
- 초안/작업 ID는 해당 탭 sessionStorage에만 보관한다. 탭 종료 후 복구는 보장하지 않는다. 프로젝트/대화 선택은 localStorage에 보관한다. 원문을 Git이나 외부 분석 서비스에 보내지 않는다.
- POST 응답이 유실되면 서버가 이미 실행했을 수 있다. 자동 재전송하지 않으며 대화 기록 확인을 안내한다. 완전한 idempotency와 서버 재시작 후 실행 복구는 후속 작업이다.
- 대화 목록은 선택한 프로젝트 경로와 정확히 일치하는 최근 50개다. 하위 경로·더 오래된 대화 탐색은 후속 범위다.
- PC 부팅부터 휴대폰 홈 화면까지 무조작 연결, SSH 키 첫 등록 UI, Markdown 답변 렌더링, 실행 기록 영속화는 후속 개선이다.
- 운영 서비스는 변경하지 않고 별도 loopback preview에서 검증했다. 적용은 리뷰 후 진행한다.

## 재현 가능한 검증

```sh
npm ci --ignore-scripts
npm run build
npm test
npm run test:integration
npx playwright install chromium
npm run test:browser
```

기존 테스트용 Chrome을 사용할 때는 `POCKET_TEST_CHROME`에 실행 파일 경로를 지정할 수 있다.

## 음성 중복 입력 추가 수정 (#9)

동일 확정 결과가 재통지되면 기존 `dictationFinal += transcript` 코드에서 `확인해 주세요확인해 주세요`가 만들어지는 것을 브라우저 fixture로 재현했다. 이제 현재 세션 results의 각 위치를 한 번씩 렌더링한다. 다른 위치에 실제로 반복된 말은 보존하며, 중간 결과 수정/삭제와 새 녹음 세션도 처리한다.

근거: [SpeechRecognitionEvent.results](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionEvent/results)는 현재 세션의 확정 결과와 갱신 가능한 중간 결과를 포함한다.

수정 전 신규 회귀 2개 실패를 확인했고 수정 후 전체 브라우저 회귀 6개 통과. 실제 휴대폰 마이크 검증은 여전히 별도이며 운영 서비스 적용 전이다.
